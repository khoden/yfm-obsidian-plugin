# YFM Preview for Obsidian

Прототип desktop-плагина: отдельная панель HTML текущего сохранённого Markdown-файла через `@diplodoc/transform`.

## Запуск

Используйте pnpm 11.5.0 (версия закреплена в `packageManager`).

```sh
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm test
pnpm exec playwright install chromium
pnpm run test:browser
pnpm run build
pnpm run install:test-vault
```

Откройте папку `test-vault` как vault в Obsidian.
Разрешите community plugins и включите **YFM Preview**, если Obsidian запросит это.
Откройте `01-YFM.md`, затем выполните команду **YFM Preview: Toggle preview** через командную палитру.
Также можно использовать иконку **Toggle YFM Preview** в левой ленте, меню вкладки исходника «…» или правый клик в редакторе.
Пункты меню называются **Открыть YFM Preview справа** и **Закрыть YFM Preview** в зависимости от состояния панели.
Все способы работают как toggle: повторное действие закрывает открытый предпросмотр.
Панель откроется рядом с редактором и будет следовать за открываемыми Markdown-файлами.
Ссылки на другие файлы из предпросмотра открываются в исходной вкладке редактора, заменяя её содержимое и сохраняя панель предпросмотра.
Если исходная вкладка закрыта, используется другой Markdown-редактор; если редакторов нет, создаётся соседняя панель.
После пересборки снова выполните `pnpm run install:test-vault` и перезагрузите плагин в Obsidian.

## Поведение

- Источник — сохранённое содержимое из Vault API, включая изменения внешним редактором.
- Событие `modify` сразу инвалидирует кеш файла и отменяет устаревший рендеринг; новая конвертация выполняется с настраиваемым debounce (по умолчанию 500 мс).
- Ключ кеша — SHA-256 UTF-8 содержимого файла; кеш хранит HTML и диагностику только в памяти, максимум 32 записи с LRU-вытеснением.
- Путь файла не входит в ключ: локальные изображения разрешаются после получения HTML из кеша.
- Базовые гарнитура, размер текста и моноширинный шрифт для кода берутся из стилей встроенного просмотрщика Obsidian при обновлении предпросмотра.
- HTML отображается в iframe с `sandbox="allow-scripts"`, с собственными CSS и runtime Diplodoc.
- При обновлении того же файла позиция прокрутки сохраняется и восстанавливается после загрузки изображений; при сокращении документа ограничивается его новой высотой.
  Переход на другой файл сбрасывает прокрутку в начало.
  Открытые каты и выбранные вкладки при обновлении сбрасываются.
- Пункт «Обновить» в меню вкладки (правый клик по вкладке или меню «…») принудительно сбрасывает запись текущего файла.

## Подсветка исходника

Теги `note`, `cut`, `list tabs` и закрывающие теги подсвечиваются в Source mode, Live Preview и встроенном Reading view.
В Reading view теги остаются видимыми, обычный Markdown сохраняет штатное отображение; цветами и фоном управляет тот же переключатель настроек.
Параметры и заголовки выделены отдельно; фон всего блока зависит от его типа и темы Obsidian.
Во вложенных блоках применяется оформление самого глубокого блока, незакрытый блок выделяется до конца документа.
Теги внутри inline-кода, fenced code blocks и комментариев не распознаются как YFM-блоки.
Подсветка включена по умолчанию и отключается в настройках плагина без перезагрузки.
Якоря `{#id}` в заголовках и параметры вкладок вроде `{selected}` используют цвет Markdown-маркеров заголовка из темы Obsidian.
Первая строка каждой вкладки выделяется жирным и подчёркиванием; вложенные обычные списки и содержимое вкладки не выделяются.
Примеры для ручной проверки — `test-vault/03-Highlighting.md` и `test-vault/04-Anchors-and-tabs.md`.

## Язык интерфейса

Плагин использует язык Obsidian: русский для `ru`, английский для остальных языков.
Локализованы команды, меню, настройки, сообщения и стандартные подписи Diplodoc; текст заметок не переводится.
Требуется Obsidian 1.8.7 или новее (API `getLanguage`).
При смене языка Obsidian перезагрузите приложение вместе с плагином.

## Настройки

В **Settings → YFM Preview** доступны задержка обновления в миллисекундах (0–60000, по умолчанию 500) и **Debug-mode** (по умолчанию выключен).
Настройки сохраняются в vault и применяются к открытым панелям без перезагрузки плагина.
Техническая строка с путём, состоянием кеша и SHA-256 видна только в Debug-mode; сообщения об ошибках доступны всегда.

## Границы прототипа

YFM includes не разрешаются; Liquid отключён, переменные и условия не вычисляются.
Специфичная разметка Obsidian не обрабатывается.
Raw HTML в исходном Markdown отключён; отображается HTML, сгенерированный трансформером из Markdown/YFM.
Блоки кода подсвечиваются штатным Prism Obsidian с оформлением токенов из текущей темы Reading view; язык задаётся после тройных обратных кавычек (например, `typescript`, `json` или `bash`).
Без языка или с неизвестным языком код отображается без подсветки.
Нет синхронизации прокрутки и рендеринга Mermaid.
Внешние изображения могут загружаться по URL; относительные локальные изображения читаются через Vault API и встраиваются как `data:` URL, без зависимости от `app://` внутри sandboxed iframe.
Мобильная версия не поддерживается.

## Автоматическая проверка

`pnpm run format` форматирует TypeScript, JavaScript, JSON и CSS через Biome; `pnpm run format:check` проверяет форматирование без изменений.
YFM-примеры в vault, Markdown и генерируемые файлы исключены из форматирования.
`pnpm run typecheck` проверяет типы; `pnpm test` проверяет кеш, debounce 500 мс, переключение файлов, устаревшие чтения и удаление.
`pnpm run test:browser` проверяет note, вложенный cut, вкладки, объединённые ячейки, термины и повторный рендеринг в sandboxed iframe Chromium.
Для использования уже установленного Chromium можно передать путь через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.
Автоматические проверки не заменяют запуск плагина в Obsidian.

## Ручная проверка

1. Откройте `01-YFM.md` и предпросмотр; проверьте note, вложенный cut, обе вкладки, таблицы, термин, картинку и якорь.
2. Измените текст и дождитесь автосохранения: спустя 500 мс после события сохранения должен появиться новый текст.
3. Быстро меняйте текст несколько раз: предпросмотр должен показывать последнее сохранение.
4. Откройте `02-Second.md`; панель должна переключиться, в том числе при переходе по ссылке из предпросмотра.
5. Включите Debug-mode в настройках и вернитесь к первому файлу: строка состояния должна показать «кеш», если файл не менялся и запись не была вытеснена.
6. Переименуйте открытый файл, затем удалите его: панель должна обновить путь, затем очиститься.
7. Измените задержку в настройках и проверьте обновление; выключите Debug-mode — техническая строка должна исчезнуть без сброса предпросмотра.
8. Переключите светлую/тёмную тему, закройте панель и откройте повторно.

## Порядок ревью

1. `src/cache.ts`: SHA-256, инвалидация, ограничение кеша и настройки трансформера.
2. `src/main.ts`: события vault, debounce, защита от устаревших чтений и жизненный цикл панели.
3. `src/document.ts`: изоляция HTML, стили, runtime и переходы по ссылкам.
4. `test-vault`: примеры и ручная проверка реальной интеграции с Obsidian.
